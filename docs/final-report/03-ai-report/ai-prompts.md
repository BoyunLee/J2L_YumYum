# AI 프롬프트 모음

## 사용 방법

- 아래 프롬프트는 그대로 복사해 사용할 수 있도록 작성했다.
- 실제 secret, token, API key, 개인 이메일은 프롬프트에 넣지 않는다.
- 외부 AI에 전달할 때는 필요한 파일명과 캡처 경로만 제공한다.
- 결과물이 실제 구현과 다르면 구현 기준으로 수정한다.

## 1. 코드베이스 분석 프롬프트

```text
내 역할은 QA, PM이야. 시간이 촉박해서 FE와 BE가 작업한 항목을 그대로 가지고 왔어.
일단 이 프로젝트 전반과 Git 커밋로그를 스캔해서 컨텍스트로 가져보자.
```

## 2. 개발 일지 학습 프롬프트

```text
Chrome 제어 도구를 통해 Honey Board의 팀 일지 목록에서 2026-05-22부터 2026-06-24까지의 일지를 오래된 순서대로 읽고,
프로젝트의 기획/설계/구현 흐름을 학습해 이후 작업 컨텍스트로 반영해줘.
```

## 3. 데모 MVP 안정화 구현 프롬프트

```text
현재 Vue/Vite + Spring Boot/MySQL + Docker 구조를 유지하면서,
관리자/PM이 행사장에서 안정적으로 시연할 수 있는 데모 MVP로 만들어줘.

핵심 사용자 흐름은 실제 OAuth 로그인, 온보딩, 냉장고, 식단 기록, 레시피 추천, 알림까지다.
외부 API는 mock/live/fallback을 지원하고 local/Docker 기본값은 mock으로 둬.
```

## 4. QA 점검 프롬프트

```text
문서화를 시작하기 전에 긴급하거나 중요한데 스스로 점검 가능한 것만 진행해줘.
Docker 실제 기동은 이미 검증된 것으로 보고,
빌드, 설정, 민감 로그, 비밀값 노출, 데모 안정성에 영향 주는 항목만 확인해줘.
```

## 5. 발표자료 목표 수립 프롬프트

```text
우리가 만들어야 하는 건 설계문서의 6개 항목,
최종 완료 보고서의 발표용 PPT와 AI 사용 보고서야.
외부 AI(Gamma 등)에게 맡길 수 있도록 프롬프트와 사용할 화면캡처, 사진자료를 별도 폴더에 정리하는 목표를 세워보자.
```

## 6. Gamma 발표자료 생성 프롬프트

```text
YumYum 프로젝트의 SSAFY 최종 발표용 PPT를 만들어줘.
발표 시간은 약 20분이고, 최소 10장 이상, 권장 14~15장으로 구성해줘.

디자인은 Toss Design System처럼 깔끔하고 밝게 구성해줘.
흰색/연회색 배경, 선명한 포인트 컬러, 짧은 문장, 카드형 정보 배치를 사용해줘.

프로젝트 요약:
YumYum은 냉장고 속 식재료를 등록하고, 유통기한 알림과 식단 기록,
보유 재료 기반 레시피 추천을 제공하는 웹 서비스야.
사용자는 OAuth 로그인 후 온보딩을 완료하고, 재고를 수기/OCR/바코드 방식으로 등록해.
관리자는 /admin에서 서비스 현황, API 사용량, 배치, 공지, 감사 로그를 확인해.

슬라이드 구성:
1. 표지
2. 목차
3. 기획 배경과 문제 정의
4. 서비스 목표와 핵심 사용자 흐름
5. 경쟁 서비스 비교와 차별화 전략
6. 전체 시스템 구조
7. DB/ERD 및 도메인 설계
8. 냉장고 등록: 수기/OCR/바코드
9. 식단 기록과 일일 영양 요약
10. 레시피 추천 구조와 mock/live/fallback 전략
11. 알림과 관리자 기능
12. 화면 흐름 및 시연 시나리오
13. 기대 효과와 향후 개선
14. 개발 후기
15. AI 사용 보고 요약

첨부 이미지와 다이어그램을 적극적으로 활용하고,
팀명/팀원/팀 사진은 플레이스홀더로 남겨줘.
```

## 7. 설계문서 생성 프롬프트

```text
아래 YumYum 프로젝트 정보를 바탕으로 제출용 설계문서를 작성해줘.
필수 항목은 요구사항 정의서, Use-Case 다이어그램, 클래스 다이어그램,
ERD, WBS & 간트 차트, 화면 설계서야.

문서 톤은 평가자가 빠르게 확인할 수 있도록 표와 다이어그램 중심으로 정리해줘.
실제 구현 스택은 Vue 3/Vite/Pinia, Spring Boot/MyBatis/MySQL,
FastAPI Pororo OCR, Docker Compose야.
```

## 8. AI 사용 보고서 생성 프롬프트

```text
YumYum 프로젝트의 AI 사용 보고서를 작성해줘.
AI를 사용한 목적, 사용한 기능, 대표 프롬프트, 산출물, 사람이 검증한 방식을 표로 정리해줘.

중요:
AI가 모든 것을 자동 생성했다는 식으로 쓰지 말고,
AI는 분석과 초안 작성, 안정화 방향 제안에 활용했고
최종 결정과 검증은 사람이 수행했다는 관점으로 작성해줘.
```

## 9. 시연 스크립트 생성 프롬프트

```text
YumYum 최종 발표 중 5분 시연 파트를 위한 스크립트를 작성해줘.
순서는 OAuth 로그인, 온보딩, 냉장고 수기 등록, 식단 기록에서 김밥 검색/저장,
레시피 추천 생성, 알림 조회, 관리자 화면 확인이야.

발표자는 PM/QA 관점에서 안정성과 사용자 흐름을 강조해야 해.
각 단계마다 화면에서 어디를 볼지, 어떤 말을 할지 짧게 작성해줘.
```

## 10. 슬라이드 검수 프롬프트

```text
첨부한 YumYum 발표자료 초안을 평가자 관점에서 검수해줘.

확인 기준:
1. 슬라이드 수가 10장 이상인지
2. 기획 배경, 목표, 일정, 시장 분석, 개발 결과, 시스템 구조, 화면 흐름, 알고리즘, 기대 효과, 개발 후기, AI 사용 보고가 포함됐는지
3. 실제 구현과 다른 기능을 임의로 추가하지 않았는지
4. secret, token, 개인 이메일 같은 민감 정보가 없는지
5. 20분 발표 기준으로 분량이 과하거나 부족하지 않은지

출력은 수정이 필요한 슬라이드 번호와 이유, 고칠 문장으로 정리해줘.
```

## 11. 설계문서 보강 프롬프트

```text
YumYum 설계문서를 평가자 관점에서 보강해줘.
단순 설명보다 요구사항, 수용 기준, 데이터 흐름, 예외 처리, 데모 성공 기준이 드러나야 해.

필수 항목:
- 요구사항 정의서
- Use-Case 다이어그램
- 클래스 다이어그램
- ERD
- WBS & 간트 차트
- 화면 설계서

각 항목마다 발표자료에 사용할 수 있는 한 줄 메시지도 함께 작성해줘.
```

## 12. 개인정보 제거 프롬프트

```text
아래 문서/슬라이드 내용을 검토해서 공개하면 안 되는 정보가 있는지 찾아줘.

찾을 항목:
- OAuth client secret
- API key
- JWT secret
- access token / refresh token
- 실제 이메일
- 실제 계정 ID
- 내부 운영 URL 중 공개하면 안 되는 값

결과는 위험도 High/Medium/Low와 수정 제안으로 표로 정리해줘.
```

## 13. 개발 후기 정리 프롬프트

```text
YumYum 프로젝트 개발 후기를 팀 발표용으로 정리해줘.

톤:
- 과장하지 말고 실제 프로젝트 회고처럼 작성
- 문제, 해결, 배운 점이 드러나게 작성
- 팀원별 역할과 한 줄 회고를 넣을 수 있게 구성

반드시 포함할 내용:
- 외부 API 장애에 대비한 mock/live/fallback 구조
- OCR/바코드/수기 입력을 하나의 재고 등록 흐름으로 묶은 점
- OAuth와 온보딩 흐름을 실제 시연 경로로 만든 점
- 문서화와 QA를 통해 데모 안정성을 확보한 점
```
