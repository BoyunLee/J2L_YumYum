# 발표자료 슬라이드 구성안

## 1. 표지

- 제목: YumYum
- 부제: 냉장고 재고 기반 식단 기록 및 레시피 추천 서비스
- 팀명/팀원 플레이스홀더
- 이미지: 서비스 대표 화면 또는 대시보드 캡처
- 핵심 메시지: “냉장고 속 재료를 오늘의 식단 결정으로 연결합니다.”
- 권장 시간: 1분

## 2. 목차

- 기획 배경
- 서비스 소개
- 설계와 시스템 구조
- 핵심 구현
- 시연 흐름
- 기대 효과와 회고
- 핵심 메시지: “문제에서 구현, 시연, 회고까지 사용자 흐름 중심으로 설명합니다.”
- 권장 시간: 30초

## 3. 기획 배경과 문제 정의

- 냉장고 재고를 기억하지 못해 식재료가 낭비됨
- 유통기한 관리가 수동적이고 번거로움
- 보유 재료와 실제 식단 기록이 분리되어 있음
- 메시지: “냉장고에 있는 재료를 오늘의 식단 결정으로 연결하자”
- 이미지/도식: 간단한 문제 흐름 `재고 망각 -> 유통기한 초과 -> 식사 결정 지연`
- 권장 시간: 2분

## 4. 서비스 목표와 핵심 사용자 흐름

- OAuth 로그인
- 온보딩
- 재고 등록
- 식단 기록
- 레시피 추천
- 알림 확인
- 이미지: `user-flow.mmd`
- 권장 시간: 1분 30초

## 5. 경쟁 서비스 비교와 차별화 전략

| 비교 항목 | 일반 냉장고 앱 | 식단 기록 앱 | YumYum |
| --- | --- | --- | --- |
| 재고 관리 | 가능 | 약함 | 가능 |
| 식단 기록 | 약함 | 가능 | 가능 |
| 재료 기반 추천 | 제한적 | 약함 | 핵심 기능 |
| OCR/바코드 등록 | 일부 | 약함 | 지원 |
| 데모 안정성 | 해당 없음 | 해당 없음 | mock/fallback |

- 핵심 메시지: “YumYum은 재고 관리와 식단 기록을 연결하고, 데모 안정성까지 설계했습니다.”
- 권장 시간: 1분 30초

## 6. 전체 시스템 구조

- Vue/Vite FE
- Spring Boot API
- MySQL
- FastAPI OCR
- 외부 OAuth/GMS/식품안전나라 API
- 이미지: `system-architecture.mmd`
- 핵심 메시지: “기능별 책임을 나누고 외부 연동은 교체 가능한 계층으로 감쌌습니다.”
- 권장 시간: 2분

## 7. DB/ERD 및 도메인 설계

- 사용자, 냉장고, 식단, 레시피, 알림, 관리자 도메인
- 식단 기록과 추천 이력을 같은 기록 축에서 관리
- 이미지: `erd.mmd`, `class-diagram.mmd`
- 보조 설명: `meal_logs`와 `meal_log_items`가 소비 기록과 추천 이력을 함께 담는 구조
- 권장 시간: 2분

## 8. 냉장고 등록: 수기/OCR/바코드

- 수기: 여러 상품 batch 등록
- OCR: 이미지 -> Pororo OCR -> GPT 구조화 -> 입력 폼 자동 채움
- 바코드: ZXing -> 식품안전나라 API -> 상품 정보 보강
- 이미지: `05-inventory-add.png`
- 보조 이미지: `04-inventory-list.png`, `06-inventory-detail.png`
- 권장 시간: 2분

## 9. 식단 기록과 일일 영양 요약

- 음식 검색
- 항목 추가
- 섭취량 입력
- 저장 후 요약 갱신
- 이미지: `07-meal-log.png`
- 핵심 메시지: “기록 저장이 끝이 아니라 요약 카드가 즉시 갱신되는 흐름입니다.”
- 권장 시간: 1분 30초

## 10. 레시피 추천 구조

- 서버가 사용자 냉장고 재고를 읽어 추천 생성
- 추천 결과 저장 및 최근 추천 조회
- `mock/live/fallback` 모드로 데모 안정성 확보
- 이미지: `08-recipe-recommendation.png`
- 보조 이미지: `class-diagram-integration-detail.mmd`
- 핵심 메시지: “추천 품질보다 먼저 시연 안정성을 보장하는 구조를 만들었습니다.”
- 권장 시간: 2분

## 11. 알림과 관리자 기능

- 유통기한 임박/만료 알림
- 공지 알림
- 관리자 대시보드, API 사용량, 배치 실행, 감사 로그
- 이미지: `09-notifications.png`, `11-admin-dashboard.png`
- 보조 이미지: `12-admin-operations.png`

## 발표 전체 체크

- 12번 시연 슬라이드에서 시간을 많이 쓰므로, 6~11번 기술 설명은 화면 중심으로 압축한다.

- 발표자료 생성 후 각 슬라이드의 이미지가 실제 `04-assets/screenshots` 파일과 연결되는지 확인한다.
